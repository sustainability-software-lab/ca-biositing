# Decisions
* [Unconstrained foreign keys: many FK columns are commented out as ’per repo convention’](datamodels-unconstrained-fk-convention.md) - About ten supply and assumption tables keep FK columns as plain ints with a ’commented out per repo convention’ note; the convention is not written down anywhere in the repo.
* [Measurements as a long observation table instead of one column per analysis](datamodels-observation-long-table.md) - Analysis record tables hold provenance only; every measured value is an observation row, which lets one schema cover many techniques but moves value meaning into lookups.
* [Decision: SQL-first pgschema workflow replaced by SQLModel plus Alembic](views-sql-first-to-alembic.md) - Why schema changes moved from a SQL-first pgschema workflow (Feb 2026) to hand-written SQLModel classes with Alembic, leaving pgschema as a diff-only validator.
* [Decision: migrations embed frozen compiled SQL instead of importing view expressions](views-compiled-sql-snapshots.md) - Why view migrations contain raw SQL strings compiled from SQLAlchemy rather than importing data_portal_views at replay time, with the trade-offs and the drift risk this creates.
* [Decision: views split across ca_biositing and data_portal schemas](views-two-schemas.md) - Why views sit in two schemas (ca_biositing vs data_portal); rationale is undocumented, so this records the known facts and labeled inferences.
* [Decision: centralize data-quality exclusions in common.py (not per-view literals)](views-centralized-qc-filters.md) - Why exclusions moved into one module, what each exclusion was added for (with PR and issue links), and the rejected per-view-literal approach.
* [Why alembic history was squashed to 0001-0004 and old revisions moved to versions_old/](squash-migration-history.md) - Records the May 2026 squash (PR #340): what was replaced, why the old revisions were parked in versions_old/, and what the trade-off is.
* [Why datamodels moved from LinkML codegen to hand-written SQLModel + Alembic (PR #112)](linkml-to-sqlmodel-alembic.md) - Records the February 2026 switch from LinkML-generated SQLAlchemy models to hand-written SQLModel classes managed by Alembic, and what it replaced.
* [Two competing name-to-id helpers (lookup_utils vs name_id_swap)](pipeline-lookup-helper-duplication.md) - lookup_utils.py and name_id_swap.py each implement replace_name_with_id_df with different signatures and commit rules; name_id_swap is the one most code uses.
* [Why the webservice has both JWT users and per-client API keys](webservice-jwt-and-api-key-split.md) - Decision record: JWT for browser and admin sessions, hashed revocable API keys with rate limits for consumers. Rejected alternatives and trade-offs.
* [Decision: Pulumi Python instead of OpenTofu/HCL for GCP infrastructure](infra-pulumi-over-opentofu.md) - Why infrastructure moved from OpenTofu HCL to Pulumi Python in Feb 2026 (PR #110), what was given up, and what remained from the OpenTofu era.
* [Decision: run Pulumi in a Linux Docker container locally, directly in CI](infra-pulumi-run-in-docker.md) - Why Pulumi commands on macOS are wrapped in the ca-biositing-pulumi Docker image (macOS gRPC crash), while GitHub Actions runs the same program directly on Linux.
* [Decision: images built to GHCR, pulled by Cloud Run through Artifact Registry proxies](infra-ghcr-via-artifact-registry.md) - Why images are built to GHCR but Cloud Run pulls them through shared Artifact Registry proxy repos (ghcr-proxy, quayio-proxy), and what replaced Cloud Build.
* [Decision: oauth2-proxy with Google login in front of the Prefect UI and API](infra-prefect-auth-oauth2-proxy.md) - Why oauth2-proxy with Google login fronts Prefect locally and in GCP, why the cloud server is internal-only, and how local and cloud auth differ.
* [Decision: keyless GitHub Actions to GCP via Workload Identity Federation](infra-wif-keyless-ci.md) - Why CI authenticates to GCP with WIF and a deployer service account instead of a stored JSON key, and which roles the deployer holds.
* [Publish analysis as committed static HTML instead of a live dashboard](analysis-static-html-gallery.md) - Charts are rendered to self-contained HTML/PNG and committed to exports/plots, then published via GitHub Pages; rejected live-serving alternatives are not documented (inferred).
* [DB tests use SQLite in-memory with selected tables, not Postgres or testcontainers](testing-sqlite-in-memory-fixtures.md) - Fixtures use SQLite in-memory engines with only needed tables and shims for Postgres-only types; testcontainers is pinned but unused.
* [ca_biositing is a PEP 420 namespace shared by three distributions](pep420-namespace-packages.md) - Why src/ca_biositing has no __init__.py and how datamodels, pipeline and webservice are separate installable packages under one namespace.
* [Pixi is the only sanctioned environment and task runner](pixi-environment-manager.md) - Project rule that all local dev runs through pixi (no bare pip/conda/venv); lists the environments and why commands go through pixi run.
* [ETL orchestrated by Prefect inside Docker Compose services](prefect-docker-orchestration.md) - Prefect server, worker and Postgres run as Docker Compose services started by pixi tasks; flows run inside containers, not on the host.
* [Phase 3 plan: align data_portal views to spec and fix has_* QC gating](data-portal-mv-alignment-plan.md) - April 2026 plan for the residue-factor volume path and QC-gated boolean flags; partly implemented, status text is stale.
* [Agent harness adopted from UW SSEC template; agent_docs/ retired (Oct 2026)](ssec-agent-harness-adoption.md) - AGENTS.md became a short entry point, rules moved to .agents/rules, Claude imports AGENTS.md via CLAUDE.md, and a test asserts agent_docs/ stays deleted.
* [AI-assisted contributions: disclose, own, and credit with Assisted-by (never Co-Authored-By)](ai-contribution-policy.md) - Policy requiring disclosure, human review, no autonomous PRs, and an Assisted-by trailer. Conflicts with Co-Authored-By attribution used by some harnesses.
* [Cloud SQL uses a grant-based control model instead of strict ownership](grant-based-cloud-sql-permissions.md) - Cloud SQL cannot support strict ownership for postgres, so the reset scripts grant privileges and set default privileges rather than transferring ownership.
* [Lookup names and qualitative values are stored lowercase, with lineage fields](lowercase-lookup-conventions.md) - ETL convention: lookup names lowercase, parameter names space-separated, use_case_name canonical, and etl_run_id / lineage_group_id populated where supported.
* [QC decisions are protected from ETL overwrite until they reach the Google Sheet](qc-decisions-protected-from-etl-overwrite.md) - Routine ETL reloads skip qc_pass and note for records with an unsynced QC decision, so analyst overrides survive until Stage 2 writes them to the source sheet.
* [Decision: store generated dashboards in a GCS bucket instead of committing them to git (#519)](dashboards-gcs-over-committed-exports.md) - Generated HTML dashboards, fingerprints and insights moved from committed exports/ files to CI-published GCS objects, with GitHub Pages as a consumer; landed Oct 19 to 21, 2026.
