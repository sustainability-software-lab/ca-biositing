## Purpose
Explains how a model class becomes visible to Alembic autogenerate, `create_all`, and `from ca_biositing.datamodels.models import X`.

## Key files
| Path:line | Role |
|---|---|
| `models/__init__.py:2` | re-exports `base` mixins |
| `models/__init__.py:5,14,31-47,53,56` | re-exports auth, core, infrastructure, people and places tables (others in the same file) |
| `alembic/env.py:25` | `import ca_biositing.datamodels.models  # noqa: F401` forces registration |
| `alembic/env.py:44` | `target_metadata = SQLModel.metadata` |
| `tests/conftest.py` | `SQLModel.metadata.create_all(engine)` on in-memory SQLite |

## How it works
Importing a module that defines `class X(SQLModel, table=True)` adds `X.__table__` to `SQLModel.metadata`. The `models/__init__.py` file imports every domain subpackage, so importing the package registers all tables. Alembic reads that metadata; autogenerate only sees what has been imported.

## Interfaces
- Input: a new table class in `models/<domain>/`.
- Output: visible to `pixi run migrate-autogenerate` (via env.py) and to package consumers.

## Gotchas
- Forgetting the re-export in `models/__init__.py` is the usual reason a new table is missing from autogenerate (documented in `src/ca_biositing/datamodels/AGENTS.md`).
- Counts disagree across docs: `grep` finds 112 `table=True` class definitions across 88 files, while README and AGENTS say 91 models. Not reconciled (see facts/datamodels-model-inventory).
- `tests/conftest.py` uses SQLite, so PostGIS-typed tables may not create there.
