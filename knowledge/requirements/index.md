# Requirements
* [Do not run pixi commands that rewrite pixi.lock while any pinned pixi is older than 0.68](tooling-pixi-lockfile-format-pin.md) - pixi.lock is format v6; pixi 0.68+ writes v7 and CI, Docker and devcontainer pin v0.63.2, so dependency changes must wait for a coordinated upgrade.
* [PRs need pre-commit passing, the full PR template, AI disclosure and human diff review](tooling-pr-ai-disclosure-and-preflight.md) - Hard gate before opening a PR: run pixi run pre-commit-all, fill every PR template section including AI disclosure and author verification, and get human approval of the diff.
* [Do not create the DB engine or open connections at import time](datamodels-lazy-engine.md) - Import-time DB connection or engine creation hangs Docker and Prefect workers. Keep engine creation behind get_engine() and imports of settings inside functions.
* [New table models must be re-exported and migrated; views are not autogenerated](datamodels-register-new-models.md) - A new SQLModel table needs its import in models/__init__.py and a pixi migrate-autogenerate revision; materialized view changes need compile-mv-fixes instead.
* [Observation upserts depend on the (record_id, record_type, parameter_id, unit_id) unique key](datamodels-observation-upsert-key.md) - Keep observation_unique_key and the ETL on_conflict index_elements in sync; the transform dedupes on the same four columns, so changing one without the others breaks loads.
* [Table changes: edit SQLModel, run migrate-autogenerate, then review the generated revision](autogenerate-then-review.md) - Required workflow for table and column schema changes; autogenerate is not complete until the file is reviewed and migrate is run.
* [Migrations must not import SQLAlchemy models or view definitions](mv-migrations-embed-raw-sql.md) - Hard rule: revision files contain frozen SQL and plain op calls, and never import ca_biositing modules, so replays stay deterministic.
* [Do not edit a revision that has been applied to a shared database; add a new revision](never-edit-applied-migrations.md) - Once a revision reaches staging or prod, fix forward in a new revision. Known in-place edits (0002 in #387, 0008 in #320) are exceptions, not precedent.
* [Keep one Alembic head: linear chain, merge revisions for conflicts](single-linear-head.md) - Invariant: the live alembic/versions chain has exactly one head, and parallel branches are resolved with a merge revision, not a DB reset.
* [Import models and settings inside task or flow bodies](pipeline-lazy-model-and-settings-imports.md) - Pipeline tasks and flows must import SQLAlchemy models, datamodels settings, and engines inside function bodies to avoid Docker import hangs; several modules violate this today.
* [DATABASE_URL uses host db inside containers; localhost on host](pipeline-db-host-in-containers.md) - Containers must reach PostgreSQL at host db; the pipeline rewrites @db to localhost only outside Docker and Cloud Run, so new DB code must go through _get_database_url.
* [Google Sheets extracts need a service-account credentials.json](pipeline-gsheet-credentials-file.md) - gspread reads a service-account JSON at CREDENTIALS_PATH (default ./credentials.json); missing or wrong file surfaces as a retried RuntimeError, not a clear auth error.
* [Admin and key-management routes must stay JWT-only](webservice-admin-endpoints-jwt-only.md) - Any new admin endpoint must depend on get_jwt_user or get_current_admin_user, never get_current_user, so a leaked X-API-Key cannot manage keys or users.
* [Deploy and infra invariants a change must keep](infra-deploy-invariants.md) - Hard infra rules to keep: internal Prefect ingress, min-1 worker, AR image paths, Cloud SQL deletion protection, shared-resource retention, secret handling, DB reset target check.
* [Analysis chart exclusions must match the portal QC definitions](analysis-qc-filter-parity.md) - Chart scripts must apply the same resource, provider, and qc_pass exclusions as data_portal_views/common.py; today they copy the lists by hand, so change them together.
* [Infrastructure loaders must be idempotent: a re-run updates rows and never duplicates them](infra-loader-idempotent-rerun.md) - Each infrastructure load must keep its natural-key select and on_conflict index on a column the transform actually fills, and the re-run duplicate tests must stay green.
* [Generated dashboards, fingerprints, drift reports and insights are never committed to git](generated-artifacts-never-committed.md) - Must never commit or force-add exports/plots/**, audit/output/env_fingerprints/*.json, audit/output/drift_report.md or data/insights/resource_ai_insights.json; a pre-commit guard enforces it.
